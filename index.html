Core Architectural Principle

"The LLM reasons. Deterministic code tests. The LLM never decides truth; replay results do."

Existing AI assistants hallucinate root causes or suggest risky whole-deployment rollbacks. Exact Culprit Finder uses the LLM strictly to rank hypotheses and narrate findings, while a seeded 1,000-request sandbox bisect engine proves the exact line mathematically.

End-to-End Agentic Execution Architecture

1. INPUT & TELEMETRY
Data Sources (SQLite)

Ingests Prometheus alerts, 1-minute error/latency metrics, 150 structured logs, deploy history, and Git/config/flag diffs. Applies Temporal Filter to rule out changes after the 2:04 PM spike.

2. PLAN & HYPOTHESIZE
Agent Brain (Claude / Offline)

Matches 504 DB_TIMEOUT log signatures against candidate changes. Ranks suspects as unproven hypotheses and schedules $O(\log_2 N)$ binary search.

3. TOOL USE & DECISION
Sandbox Bisect & Pair Engine

Deep-copies state into an isolated sandbox. Replays 1,000 seeded requests (Random(42)) reverting halves (8→4→2→1) or testing pairs (A, B, A+B), then diffs individual keys.

4. ACTION & VERIFICATION
Human Gate & Live Proof

Blocks apply_fix until human clicks Approve. Applies minimal 1-key patch, replays verification window (42% → 0.3%), and generates Markdown/PDF report.

All 14 Deterministic Agent Tools

Exposed both as Python functions in backend/tools.py and Anthropic tool-calling JSON schemas.

claude-sonnet-4-6 Tool Schemas
Group 1: Investigate (6 Tools)
  • 1. get_alerts()
    Fetches firing alerts & severity timestamps.
  • 2. get_metrics(start, end)
    Returns 1-min error_rate % and p95_ms buckets.
  • 3. get_logs(start, end, level)
    Queries structured service logs & 504 stack traces.
  • 4. get_deploys()
    Lists release rollouts & build versions.
  • 5. get_git_commits()
    Lists code commits, config edits & feature flag flips.
  • 6. get_dependencies()
    Returns upstream/downstream service topology graph.
Group 2: Test in Sandbox (5 Tools)
  • 7. create_sandbox()
    Creates isolated in-memory deep copy of prod state.
  • 8. revert_changes(change_ids)
    Reverts specified commits/configs/flags in sandbox.
  • 9. run_replay(sandbox_id)
    Replays 1,000 seeded requests; returns failure_rate & p95.
  • 10. diff_config(change_id)
    Extracts individual key/value deltas from a change.
  • 11. test_single_value(sandbox_id, key)
    Reverts a single setting key to prove line-level causality.
Group 3: Act & Report (3 Tools)
  • 12. apply_fix(key, value) 🔒 HUMAN GATED
    Returns APPROVAL_REQUIRED error unless human operator clicks Approve.
  • 13. verify_recovery()
    Runs post-fix live verification window & checks SLA (<1% error, p95 within 10% baseline).
  • 14. generate_report()
    Compiles deterministic timeline, bisect table & CI prevention rules into Markdown/PDF.
Safety Controls & Guardrails
  • Hard Approval Gate: apply_fix() checks incident.approved == True in code; the agent cannot bypass it.
  • Zero-Touch Sandbox: Replay testing runs on copy.deepcopy() state.
  • Honest Epistemic Labels: Conclusions are strictly badged PROVEN or NOT PROVEN based on replay math, never LLM prose.
Known Limitations
  • Non-Deterministic External Outages: Third-party API blackouts or hardware failures that don't reproduce in recorded traffic replay yield NOT PROVEN (demonstrated in Scenario 3).
  • Stateful DB Migrations: Schema drops require snapshot restoration rather than config bisect alone.
Future Scope
  • eBPF Shadow Traffic Capture: Live Godaemon/Envoy tap for zero-overhead traffic recording in Kubernetes.
  • 3-Way & N-Way Combinatorial Group Testing: Extending pair-testing to Dorfman group testing for multi-service microservice meshes.
